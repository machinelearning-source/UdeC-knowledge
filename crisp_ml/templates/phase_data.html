2. Data Engineering

How the questions and the index become a clean modeling table, and how it is split without leakage. Script: scripts/build_dataset.py.

Selected sources and why

  • Validation questions: the only source with ground truth (expected document and page). Old Spanish file names were mapped to the current English ones.
  • KnowBot index: the same {{ quality.indexed_fragments }} fragments and embedding model (paraphrase-multilingual-MiniLM-L12-v2) that KnowBot uses, so the model learns on exactly what it will re-rank.
  • Not used: the language model translation step of KnowBot (it needs a paid or rate-limited API and is not reproducible) and the answers of the language model (they are a consequence of retrieval, not an input).

Candidate generation

For each question, the candidates are the union of the 25 fragments closest by meaning (cosine similarity), the 15 best BM25 keyword matches, and the exact calendar-activity and article matches KnowBot already uses. This reproduces KnowBot's searches, gives {{ "{:,}".format(quality.raw_rows) }} rows (about 32 per question) and contains the expected page for {{ quality.questions_with_expected_page_in_candidates }} of {{ quality.questions }} questions.

Cleaning: missing values, duplicates, inconsistencies and outliers

Encoding, scaling and normalization

  • bm25, bm25_rank, cosine_rank, chunk_chars, knowbot_rank, page_bm25_sum: constant imputation (300 for missing ranks), log1p, standardization.
  • Other numeric features: median imputation (a safeguard; there are no other missing values), standardization.
  • document: one-hot encoding, ignoring unseen categories.
  • Per-question z-scores (cosine_z, bm25_z, page_max_cosine_z) are computed from the candidates of the same question only. They use no label and no other question, so they do not leak information.

All of this is a scikit-learn ColumnTransformer inside the model pipeline. It is fitted only on the training data of each fold, and on the 80 training questions for the final model.

Partitions and leakage prevention

  • Unit of splitting = question. All candidates of a question always stay in the same partition. Splitting rows at random would put fragments of the same question in training and test.
  • Test set: {{ split.test_question_ids|length }} questions (20%), stratified by expected document, seed {{ split.seed }}: ids {{ split.test_question_ids|join(', ') }}. They are used once, after model selection.
  • Training and validation: the other {{ split.train_cv_question_ids|length }} questions, with grouped 5-fold cross-validation (GroupKFold by question) for model comparison and tuning.
  • Preprocessing: fitted inside each training fold (pipeline), never on validation or test rows.
