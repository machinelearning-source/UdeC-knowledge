Which algorithms were compared, why, how they were tuned, and what each experiment taught. Script: scripts/train.py; models and preprocessing: knowbot/model.py.

All three learned models use the same preprocessing pipeline (Phase 2), the same 23 features, seed 42 and the same folds, so their results are directly comparable. Each predicts the probability that a fragment comes from the expected page; candidates are then sorted by that probability.

How domain knowledge shaped the model

  • Exact lookups first: calendar activities and article numbers are matched by their official names, because the 71 calendar lines are almost identical for a vector model.
  • Keywords next to vectors: questions quote Spanish institutional names that vectors blur, so BM25 features were added.
  • Pages, not fragments: an answer usually spans several fragments of one page, which led to the page-vote features (Experiment 2), the most important ones in the final model.
  • Compare within a question: similarity values depend on how a question is phrased, which led to the per-question z-scores (Experiment 3).
  • Split by question: the model will meet new questions, never new fragments of a known question, so every split is by question.
